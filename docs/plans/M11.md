### 18.1 状态层重构与撤销栈（前置步骤 M11-0，无行为变化）

**文档状态 / UI 状态边界**（只有文档状态可撤销）：

| 类别 | 内容 | 存放 |
| --- | --- | --- |
| 文档状态（入撤销栈） | `clips: Clip[]`（池序 = 创建序，决策 #13）+ `timeline: string[]` | 收敛为单一 `EditorDoc` state |
| UI 状态（不入栈） | 选择 selectedId、预览模式 mode、playhead、pps/滚动、check 结果 | 维持现状各自 useState/useRef |
| 旁路状态（不入栈） | files（增删含 probe 副作用，不可逆）、clip 的 rot/crop/lockRatio（TIMELINE.md §17.5 覆盖清单不含加工编辑） | files 独立 state；rot/crop 直接改 doc 不经栈 |

**命令 = 快照对**（TIMELINE.md §17.5 范式的落地形态）：

```ts
interface DocSlices { clips: Clip[]; timeline: string[] }   // 结构共享，快照近乎零拷贝
interface TimelineCommand {
  readonly label: string;
  readonly before: DocSlices;                               // 手势提交时冻结
  readonly after: DocSlices;                                // id 在构建时分配并冻结于此
  apply(doc: EditorDoc): EditorDoc;                         // = { ...doc, ...after }
  invert(doc: EditorDoc): EditorDoc;                        // = { ...doc, ...before }
  toJSON(): CommandJSON;                                    // 序列化留口（会话恢复 v1 不做，单测覆盖 round-trip）
}
type CommandBuilder = (doc: EditorDoc, ctx: BuildCtx) => TimelineCommand | null;
// BuildCtx = { source(clipId): { fps, duration } | null（钳制用）, newId(): string }
// newId 在构建时调用并写入 after → 重做复现同一 id（单测基线 6）
```

**builder 清单**（一次用户手势 = 一条命令；no-op / 取消 / 非法落点返回 null 不入栈）：

| 手势 | builder | after 内容 | no-op 条件 |
| --- | --- | --- | --- |
| 素材卡「剪出片段」/ 批量建片段 | `buildCreateClip(clip: Omit<Clip,"id">)` | clips 追加（池序 = 创建序）+ timeline 追加 | 无（一定产生变化） |
| 池「+」加入轴末尾 | `buildAppendToTimeline(clipId)` | timeline 追加到末尾 | **已在轴上**（不重排，与"加入"语义一致） |
| 拖入轴 / 块拖动 | `buildInsert(clipId, index)` | timeline 插入（已在轴 = 移动语义） | 落点与现位置等价 / 片段不在池 |
| 整块拖拽重排 | `buildReorder(from, to)`（内部即 insert 移动） | timeline 重排 | from === to |
| Delete / 块 ✕ / 拖出边界 | `buildRemoveFromTimeline(clipId)` | timeline 去 id，**clips 不动**（池保留） | 不在轴上 |
| C 切割 | `buildSplit(clipId, productTime)` | 原 clip 删除，两条新 clip 入池，timeline 原位替换为两个新 id | 距片段边缘 <1 帧 / 播放头不在片段上 |
| 修剪拖动 pointerup | `buildTrim(clipId, edge, srcTime)` | 该 clip 的 seg 端点变化 | 钳制后与原值相等（比**有效区间**，不比表示形态） |
| 右键"移除并删除池片段"（确认后） | `buildRemoveAndDelete(clipId)` | 复合：timeline 去 id + clips 删条目 | 片段不存在 |
| 批量手势（一次改多个） | `buildComposite(label, builders)` | 顺序施加各 builder 的结果合成一条 | 全部子命令皆 no-op |

> **M11-0 落地时的三处补充**（2026-09-24，行为规格不变、实现需要）：
> ① **剪出片段**要单独一条 builder——上表原列的手势都假定片段已在池里，但"剪出片段"本身也改文档，
> 而 §17.1 不变量 4 要求所有操作可撤销，否则 Ctrl+Z 会跳过它去撤销更早的手势；
> ② **批量手势**（`batchAddClips` 等）需要 `buildComposite` 合成，否则"一次手势 = 一条命令"会被破坏；
> ③ **池「+」与拖入轴拆成两条**：前者是"仅在不轴上时追加"（已在轴上 = no-op，不重排），后者是插入/移动语义
> （`buildInsert` 的 `index` 会**钳制到 `[0, len]`**：负数 → 0、`NaN`/越界 → 末尾；调用来源只会给出合法整数）。
> 另外 `buildTrim` 的 no-op 判定按**有效区间**比较：`seg: null` 与 `{0, 源时长}` 内容相同，只因为写法
> 不同就入栈会留下"撤销了但看不出变化"的脏历史（写入时仍规范成 `seg: null`）。

**钳制规则**（进 builder，源数据经 BuildCtx）：split 左右两段各 ≥1 帧（fps 缺失按 30）；trim 新端点 ∈ [0, 源时长] 且区间 ≥1 帧（in 边 ≤ out − 1 帧）。段长 <0.05s 判空段（导出映射 `segment: null`）沿用现有规则。源未探测（`durationSec` 未知）时 split / trim 直接判非法。

**栈 hook**（`utils/undo/store.ts::useUndoStack`）：内部以 docRef 镜像读最新文档（事件时机构建，无 stale 闭包）；`execute(builder)` null 直接返回、成功则 `setDoc(cmd.apply)` + past.push + **清空 future**；`undo/redo` = pop → `setDoc(invert/apply)` → 对面栈 push；栈上限 100 条。
另有 `applyRaw(update)`：不经栈直接改文档，供**旁路状态**（片段 rot/crop 加工、素材删除的联动清理）使用——这些不进历史，所以不能假装它们走命令栈。
栈的**规则**抽成同文件的纯核心 `createUndoStack(limit)`（栈用 ref 持有、不进 render，一个版本号驱动 `canUndo`/`undoLabel` 刷新），hook 只负责"读最新文档、写 state"——这样"null 不入栈 / 成功清空重做链 / 上限丢最旧"可以脱离渲染单测。

**单测基线**（`commands.test.ts`，纯函数脱离 React）：① split→undo→redo 后文档与首次 apply 逐字节 deep-equal（含 id）；② 命令 toJSON→fromJSON round-trip 后 apply 结果一致；③ no-op（同 index 重排 / 边缘切割）返回 null 且栈不增长；④ 修剪 Esc 取消（builder 未提交）不入栈；⑤ 连续 A、B 两命令 undo 两次精确回到初始（顺序正确）；⑥ 重做复现同一 id。补充钳制域用例：trim 出界钳到源边界 / 1 帧最小；波纹删除后 clips 不动。**测试载体 Vitest**（`pnpm add -D vitest` + `pnpm test` 脚本）；若离线装不上，退回 `node --experimental-strip-types` 直跑同一断言集（实现时先探明，二选一写死在 package.json）。

### 18.2 几何模块（`ClipTimeline/geometry.ts`，M11-1）

```ts
interface Geometry {
  pps: number; starts: number[];            // 每块成品内起点（秒）
  contentWidth: number;                     // = round(total × pps)，世界宽
  block(i): { left: number; width: number };// left = round(starts[i] × pps)
}                                           // width = round(end_i × pps) − left   ← 差值法（TIMELINE.md §17.3）
timeToX(t) = round(t × pps);  xToTime(x) = x / pps;   ← 实装取 round，按 §17.3 的 x = round(t×PPS)（§17 优先于本草图）
```

- **PPS 钳制**：硬区间 [2, 500]；动态下限 = `max(2, 6 / 最短片段时长)`——最短块渲染宽 ≥6px，杜绝 M9-3 类重叠在极端缩小下回归
- **适应窗口**（`\`）：`pps = clamp(viewportW / total)`
- **刻度自适应**：目标间距 ≥60px → `step = tickStep(60 / pps)`（geometry 内置：取 **≥ 目标**的最小整刻度——2026-09-25 实施时更正：原写的 `pickTickStep` 是剪切页"总长 ≤16 格"语义，套在这里会把间距压到 60px 以下、标签互相叠）；标签用总帧数时间码（§18.5，fps 取轴上首个片段的源帧率、缺省 30）
- **迁移**：M9-3 的容器像素排布（trackW 换算 + minWidth 保底）整体删除，`xToTime/timeToX` 换 geometry 纯函数；`ResizeObserver` 保留（viewport 宽用于 fit 与缩放锚点）

### 18.3 缩放与滚动（M11-2）

- 结构：外层 `overflow-x: auto`（细滚动条样式沿用全局），内层世界坐标 div `width: contentWidth`；播放头/块/刻度全部世界坐标定位，随内容滚动，无补偿计算
- 滚轮（无 Ctrl）：deltaY/deltaX 统一转 `scrollLeft`（编辑器惯例，Windows 触控板横向滚轮天然支持）
- **Ctrl+滚轮以鼠标为中心**：`preventDefault`；`factor = exp(−deltaY × 0.0015)`；`t_anchor = (scrollLeft + mouseX) / pps`；`pps' = clamp(pps × factor)`；同帧写 `scrollLeft = t_anchor × pps' − mouseX`（先改 pps 再补偿 scroll，无视觉跳动）
- `+`/`−`：以视口中心为锚（同公式，mouseX 取半宽）；`\`：fit
- PPS 为页面级 state（Workbench 持有，ClipTimeline 经 props + onChangePps 交互；ref 镜像供 imperative 路径读）

> **M11-2 实施注记**（2026-09-25）：① PPS 初始 = `PPS_MIN`，用户手动缩放（滚轮/+/−/\）前 ClipTimeline 在视口测量与片段变化时自动 fit（M11-1 行为的延续；auto-fit 走 `useLayoutEffect` 保持单帧绘制等价、写入时同步推进 ppsRef），首次手动操作后交还控制权；② 滚轮必须原生**非 passive** 监听（React 挂 root 的 `onWheel` 是 passive，`preventDefault` 无效）；③ pps 的 ref 镜像在 ClipTimeline 内（连续两次 Ctrl+滚轮之间可能不渲染，读 props 拿到陈旧值——渲染期同步 + 写入时立即推进，同 undo/store 的 docRef 模式）；**连发同帧时缩放基准取 pendingScroll（cur 档 pps 下的目标 scrollLeft）而非 el.scrollLeft（上一档旧值），否则触控板连发会锚点漂移**；④ scroll 补偿走 `useLayoutEffect([pps])`（DOM 已按新 pps 更新、绘制未发生 → 同帧无跳动，即本节"先改 pps 再补偿 scroll"的落地形态）；⑤ +/−/\ 的 useHotkeys 暂挂 ClipTimeline（时间轴全模式常驻可见、未按 preview mode 门控；M11-8 快捷键全表整合时统一口径）；⑥ 键控缩放步进因子 1.2 为实现自定常量（规格只给了滚轮系数 0.0015）。

### 18.4 播放头渲染路径（M11-3，脱离 React）

- Workbench 持 `playheadRef`（数值）；ClipTimeline 挂载时把播放头 DOM 注册进 `playheadElRef`
- ProductPreview 的 rAF tick 内追加两行：`playheadRef.current = t`；`el.style.transform = translateX(t × pps px)`（transform 免 layout）——**整条路径 0 个 setState**
- React 的 playhead state 降频为离散镜像：仅 pause / seek / 段切换 / 结束时 `setPlayhead`（时间读数、导出逻辑用）；ProductPreview 进度条改**非受控**：ref 每帧直写 `.value`，拖动经既有 seekRequest（nonce）通路
- pps 变化：effect 依赖 pps，重写一次 transform（读 playheadRef）
- **跟随滚动**：播放中 `playheadX > scrollLeft + 0.9 × viewportW` 时 `scrollLeft = playheadX − 0.1 × viewportW`（越界沿触发一次，不逐帧）
- **播放头吸附片段边缘**：标尺点击/拖动 seek 时，距最近片段边缘 ≤ `8px / pps` 秒 → 吸附（TIMELINE.md §17.3 吸附窗）
- 验证：React DevTools commit 计数 = 0/帧（TIMELINE.md §17.9②）

> **M11-3 实施注记**（2026-09-25）：① `playheadElRef`/`scrollElRef` 由 Workbench 持有、ClipTimeline 注册（播放头 span 与滚动容器；后者每次渲染后同步——空/非空轴间会换元素），ref 以结构化 `{ current }` 类型传给 ProductPreview；② ProductPreview **仅在成品模式挂载**——切走预览模式 unmount 后 tick 停，离散 effect 兜住终态，切回时既有 nonce seekRequest 通路把播放头同步回去（Workbench 读 `playheadRef` 而非离散 state，防丢播放位置）；③ tick 的逐帧 `onPlayhead`（原每帧 setState）改为 ref + transform + 进度条 .value + 跟随滚动四连直写；离散汇 `onPlayheadDiscrete`（ref + state + transform 直写）覆盖 **seekInternal / 段切换（switchTo 内）/ 暂停（playing true→false 沿 + video onPause 的 `syncDiscreteFromVideo`）/ 结束 / 复位**；④ 进度条非受控（defaultValue），tick 每帧直写 `.value`（`draggingRef` 门控：拖动中挂起，防视频滞后位置回弹覆盖拖动值），`[playhead]` effect 做离散同步；⑤ seek 吸附抽成 `geometry.snapToEdge` 纯函数（边缘 = 各块起点 + 总时长，块连续故即全部边缘），Alt 旁路（§17.8 的 M11-3 半；修剪侧归 M11-6）；⑥ `usePlaybackHotkeys` 加 `getCurrentTime`（离散镜像下 ←/→ 必须取实时位置；剪切页等不传该参行为不变）；⑦ Workbench 离散同步 effect `[playhead, pps]` 重写 transform——事件路径已在离散汇/seek 内直写（防 state 同值 bail-out 漏写），effect 兜 pps 变化与离散 state 变化（span 裸重挂载不经 effect，由 auto-fit 改 pps / 离散汇连带覆盖）；⑧ 进度条拖动经 onChange 直调 `seekInternal`（nonce effect 调用的同一函数）——§18.4 原文"拖动经 seekRequest（nonce）通路"按实际通路更正；⑨ **披露**：标尺"拖动 seek"（scrub）自 M9 起未实现（只有点击 seek），§17.4 的拖动语义归后续批次补。

### 18.5 七操作接线（M11-4/5/6/8）

- **选择**：块 onClick → selectedId（UI state）；点空白取消；块组件 `React.memo`（props = clip 数据 + 几何 + 选中态）
- **波纹删除**（Delete / 块 ✕ / 拖出边界）：统一走 `buildRemoveFromTimeline`。**行为变更**（对齐决策 #13）：时间轴删除不再连带删池卡片——池卡 ✕ 才是真删（直接改 doc 不经栈）；右键"移除并删除"= 确认后的复合命令
- **切割**（C / 右键 / 菜单）：读 `playheadRef` → geometry 命中片段 → 源内换算 `sourceSplit = clip.in + (t − starts[i])`（TIMELINE.md §17.2）→ `buildSplit`。新片段起点帧缩略图按新 key 自动重取（现有 effect 天然支持）
- **边缘修剪手势状态机**（块 pointerdown 内判定，与拖拽重排互斥）：
  1. **热区**：扫描全部块边缘取**全局最近**者，≤8px 命中（相邻块共享边界只归属更近一侧，天然消歧）
  2. 命中 → 修剪手势：`cursor: ew-resize`，移动 ≥4px 激活（死区与 useDragSort 同参）；未激活松手 = 普通点击（选中）
  3. 拖动中：本地 `trimPreview {clipId, edge, seg}` 驱动 tooltip（新入/出点**总帧数时间码** + 新时长 + copy/transcode 徽标）；经 `onTrimPreview` 上抛，Workbench 将 previewSeg 融合进 derived payload → **check_pipeline 防抖 300ms**（徽标实时，TIMELINE.md §17.4）
  4. **关键帧吸附**：开启时距源关键帧 ≤ `8px / pps` 吸附；keyframes 按源懒加载（listKeyframes + B1 缓存，Workbench 维护 keyframesBySource）；**S 键切换**（默认值 = 设置项 keyframeSnap，切换 write-through 回写设置，决策 #30）
  5. pointerup → `execute(buildTrim)`（连续拖动只在松手入栈一条）；Esc / pointercancel 丢弃并清 preview
  6. **双击边缘** = 修剪到播放头（播放头在片段内时）
  7. 未命中热区 → 原有 useDragSort 重排路径（onReorder → `buildReorder`）
- **总帧数时间码**（`utils/time.ts::formatTimecode`）：`frames = round(t × fps)` 先取总帧再分解 HH:MM:SS:FF（TIMELINE.md §17.3，避免 59.99s 进位错）；tooltip 附总帧数
- **右键菜单**（自研 `components/ContextMenu`：fixed 定位、Escape/点击外部关闭、无依赖）：切割（播放头处）/ 波纹删除 / 移除并删除池片段（confirmDialog）/ 加工 / 撤销 / 重做 / 适应窗口
- **快捷键**（product 模式分支扩展，输入焦点忽略规则不变）：C / S / Delete / Ctrl+Z / Ctrl+Shift+Z / +/−/\\（TIMELINE.md §17.8 全表）

> **M11-4 实施注记**（2026-09-25）：① 选中为独立 UI state `selectedClipId`（不入栈；不再从 edit mode 派生——修复 R2-2 CR 发现的"成品模式 Delete 恒空"遗留项）；块点击 = 选中 + 进加工视图（过渡形态：加工的直达入口保留到 M11-8 右键「加工」落地后再裁；池卡 onOpen 进加工不置选中，与块点击不对称，M11-8 一并裁决）；点空白 = seek + 取消选择；选中片段离开时间轴后同步清选（effect 兜底）。② 波纹删除（块 ✕ / 拖出边界 / Delete）统一 `buildRemoveFromTimeline`——只出轴、池保留、可撤销；池卡 ✕ = 真删（`applyRaw` 直接改文档不经栈、**联动清轴上残留项**，直接依据即 §18.5 本节正文；可撤销版 = M11-8 右键「移除并删除池片段」复合命令；与撤销栈快照对的复活冲突见 §18.9 风险表，M11-7 接线时清洗）。③ Delete 键 enabled = 有选中（不再限 product 模式——时间轴全模式可见，§17.8 的 Delete 行无模式限制）。④ 块组件 `React.memo` 推迟：M11-3 已消灭逐帧重渲染（性能痛点本体），memo 剩余收益仅在选中切换的两次块级重渲染；要生效需先稳定 `useDragSort` 的 beginDrag/rowCls 引用（跨批重构）——归 M11-9 按埋点数据决定。

### 18.9 风险与对策

| 风险 | 对策 |
| --- | --- |
| 修剪热区与整块拖拽的 pointerdown 归属冲突 | 全局最近边缘 ≤8px 优先命中修剪；两者共享 4px 死区（未达阈值松手 = 点击选中） |
| 播放头降频镜像与播放器 seek 不一致 | ref/state 只在离散事件强制同步；seek 沿用 nonce 机制 |
| StrictMode 双渲染 | 命令只在事件处理器构建（不进 render）；ref 直改 DOM 的 effect 幂等 |
| 修剪拖动中 check_pipeline 风暴 | previewSeg 融合 + 300ms 防抖 + B1 缓存兜底；仍慢则降级为"松手才检测"（后备，徽标实时性让位） |
| 极端缩小下 sub-pixel 块重叠回归 | 动态 PPS 下限保证最短块 ≥6px（§18.2） |
| 结构性 `applyRaw`（池卡 ✕ 真删 / 素材删除）与撤销栈快照对的复活冲突：栈内 before/after 仍引用被删实体，M11-7 接线后 Ctrl+Z 会把整切片换回（片段甚至素材"复活"） | M11-7 接线时清洗：undo/redo 前校验快照引用的 clip/file 是否仍存在，含已删实体的命令丢弃或整体清栈 |
| 撤销栈内存（100 条快照） | 不可变结构共享 + 栈上限 100 |
| Vitest 离线装不上 | 退回 node 原生 TS 直跑同一断言集（§18.1） |
