## 19.1 `M14-1` 成品连播在片段边界停住（`BUG-014`）

**现象**（用户 2026-09-28 实机报告）：工作台成品模式按下播放后，播到片段边界停住，无法连续播完整个时间轴。"只能点开每个片段单独看"。

**已知线索**：`HANDOFF.md` 未决问题表里早有同一条——「`ProductPreview.switchTo` 段边界可能误报 `onPlayingChange(false)` 致连播停住」，当时的**静态推演结论是"不成立"**。用户实机现象与之吻合 → **推演结论不可信，必须先复现定位，禁止直接改代码**（与 `BUG-012` 的教训同源：`switchTo` 里混着 rAF、`onEnded`、`pause()` 的异步 `onPause` 回调与 React 批处理四重时序，读代码推不出来）。

**复现步骤**（真机 GUI，工具与坑见 [gui-e2e/README.md](../gui-e2e/README.md) §2 与 [TESTING.md](../TESTING.md) §3.3）：

1. 导入 2 个夹具素材 → 各剪 2 段、共 4 段入轴（确保边界既有跨源也有同源相邻段）；
2. 成品模式点「播放」；
3. 用 `eval` 高频轮询（**断言优先 `eval`，别用截图**）：活动槽 `paused` / `currentTime`、`segIdx`、页面时间读数，观察在哪一段边界停止推进；
4. **执行前必须先 `focus` 窗口**——被遮挡窗口的 rAF 停摆，会把"后台节流"误判成"连播停住"（本仓已踩过的坑）。

**候选根因（待复现定位，三条互斥或并存）**：

| # | 假设 | 落点 |
| --- | --- | --- |
| ① | `switchTo` 内对**离场槽**调 `pause()` → 异步派发的 `onPause` 里用 **React state `slot`** 判断 `name === slot`，与 `setSlot` 的重渲染竞态 → 误报 `onPlayingChange(false)` | `ProductPreview` 的 `onPause` 处理器 |
| ② | rAF tick 与 `onEnded` **双触发** `switchTo` → 活动槽来回翻转，新活动槽停在旧位置（`currentTime ≥ srcEnd`），tick 立刻又判越界 | rAF tick 的越界分支 + `onEnded` |
| ③ | 预载槽 `play()` 补挂遗漏（`onLoadedMetadata` 对**已加载**的媒体不再触发） | `onLoadedMetadata` / 播放态 effect |

**修法方向**：

- 假设 ① 成立 → 离场槽判定改用 **ref**（`segIdxRef`/落槽 ref）而非 React state，或给 `pause()` 加 `switchingRef` 抑制门（`HANDOFF` 已给方向，但**以复现结论为准选其一**）；
- 假设 ② 成立 → `switchTo` 加"同一次越界只切一次"的幂等门（段切换序号比对），`onEnded` 退化为兜底；
- 三条都不成立 → 继续按"解码 → 归一 → 合成 → 传输 → 呈现"顺序排查，**不先猜 React 渲染**（性能排查同口径，见 [PLAN.md](../PLAN.md) 风险登记）。

**验证**：`TC-044`（真机 GUI：4 段连播跨段不停、播到末尾正常停止、可中途 seek 后继续播）。

**披露**：本项**不新增功能**——`DESIGN.md` §3.8 的"近似连播"承诺本来就在，修好只是回到承诺。

## 19.2 `M14-2` 页面重置 / 换素材

**现状**（2026-09-28 代码核对）：

| 页面 | 换 / 加文件 | 清空当前操作 |
| --- | --- | --- |
| 剪切 `pages/Cut` | **仅空态有**「打开视频文件」，加载后**无任何入口** | 片段只能逐条 ✕ / Delete 删最后一个 |
| 编辑 `pages/Editor` | **仅空态有** | 旋转有「重置」（仅旋转参数）；裁剪无 |
| 合并 `pages/Merge` | 「添加视频」常驻 | 逐行 ✕ 删到空（回到空态） |
| 工作台 `pages/Workbench` | 素材区「添加」常驻 | 逐卡 ✕；时间线 / 撤销栈无清空入口 |

（拖拽导入是剪切/编辑页当前唯一的换文件途径——App 层原地分发 `initialFiles`，本批**保留不变**。）

**方案**：统一为**两个动作**，不合成为一个按钮（一个是文件选择器，一个是破坏性操作）：

- **换素材**：剪切/编辑页头右侧加「打开其他视频」→ 直接复用既有 `loadFile`（它已把 per-file 状态逐项清干净：`info` / `keyframes` / `segments` / `selection` / `currentTime` / `duration` / `probeError`；`M15` 落地后 `loadFile` **同时清删除列表** `marks`——它也是 per-file 状态）→ **几乎零新增状态代码**；合并/工作台维持既有「添加」语义（追加，不清空）。
- **重置**（**2026-09-28 用户裁决：卸载文件、回到本页空态**，与 `TC-046` ① 的口径一致）：
  - 剪切页 / 编辑页 = **卸载当前文件**（`inputPath = null`，回到可点「打开视频文件」的空态）**并清掉本页全部编辑产物**——剪切页：片段 + **删除列表**（`FR-326`）+ 选区 + 播放位置 + 探测/关键帧状态；编辑页：`NO_ROTATE` + 选区 `null` + 质量档位回 `settings.quality`（卸载后这些状态本就不会显示，但必须清，否则下一个文件会继承上一个的加工态）；
  - 合并页 = 清空列表 + 文件名回默认（见 `M14-3`）；
  - 工作台 = 清空工程：`files` + `timeline` + `clips` + **`undoStack.clear()`**。
- **二次确认**：有"未导出的操作产物"时才弹（剪切页有片段**或删除标记** / 编辑页有非恒等旋转或选区 / 合并页有文件 / 工作台有素材）。工作台「清空工程」**始终确认**（破坏面最大）。
- **重置后落点**：剪切/编辑页**停在本页空态**（可再点「打开视频文件」），工作台停在空工程态（用户 2026-09-28 裁决）。

**工作台的撤销栈必须一起清**——[plans/M11.md](./M11.md) §18.9 的硬约束：撤销栈快照里带着片段 id，素材/片段被真删后历史被毒化，`M11-7` 已定为"真删了片段就整体清栈"（`FR-1737`）。清空工程是真删全部，**必须**走 `undoStack.clear()`，否则后续 Ctrl+Z 会"复活"已删内容。

**与既有决策的关系**：不冲突。决策 #24「设置变更一律不重置页面」管的是**设置驱动**的重置；本项是**用户显式发起**的动作，两者正交（已写入 `ADR-036`）。

**规格落点**：`UI.md` §9.2（统一总则）+ 各页小节。**验证**：`TC-046`。

**落地记录（`M14-2`，2026-09-28）**：

- `pages/Cut`：页头右侧新增「打开其他视频」（复用 `loadFile`）+「重置」；重置在"有片段**或删除标记**"时二次确认，随后**卸载文件回空态**，并把 `info` / `keyframes` / `segments` / `marks` / `selection` / `currentTime` / `duration` / `probeError` 全部清空、播放器暂停。空态已有大号「打开视频文件」入口，故这两个按钮**只在有文件时出现**；
- `pages/Editor`：`EditorHeader` 加同一对按钮（同样只在有文件时出现）；重置的二次确认门槛 = 非恒等旋转（`rotate` 工具）或存在选区（`crop` 工具）；

## 19.5 `M14-5` 放大预览双态 + 成品预览套用裁剪变换

本任务同时兑现一条**新需求**（`FR-354`，编辑时的双态预览）和一条**既有规格的回填**（`BUG-015`，成品预览本就承诺"套用各片段旋转/裁剪变换"）。两者**共用同一个纯函数**，故合批。

### 19.5.1 后端实际做了什么（预览要与之一致）

后端放大链是 `command.rs::crop_zoom_args`：

```text
crop=<w>:<h>:<x>:<y>,scale=<outW>:<outH>:flags=lanczos
```

`outW:outH` 默认 = **显示分辨率**（`DESIGN.md` §3.5：默认放大回原视频分辨率）。也就是说：**裁切出来的矩形被拉伸填满整个显示画面**，宽高比**不做保持**（各向异性）。预览必须照这个语义做，否则"所见"与"所得"仍然不一致。

### 19.5.2 预览的等价实现（纯 CSS 线性变换）

设归一化选区 `(nx, ny, nw, nh)`、显示空间尺寸 `dims`。要实现"裁切区铺满 dims 大小的框"，只需把**整帧**按 `1/nw`（横）× `1/nh`（纵）放大后平移：

```text
left   = −nx / nw × 100%        （百分比基准 = 外层框，即显示空间）
top    = −ny / nh × 100%
width  = 100 / nw %
height = 100 / nh %
```

这与 `crop → scale` 的输出**逐像素等价**（同一线性映射，差异只来自 lanczos 重采样与偶数对齐）。落地为一个纯函数，放 `src/utils/crop.ts`（与 `pxToCrop`/`cropToPx` 同域），**配 Vitest 用例**（退化输入 `nw/nh → 0`、整幅 `nw=nh=1` 时退化为恒等、比例验证）。

**与旋转的叠加顺序**：选区坐标在**显示空间**（旋转后的画面）里——所以缩放框在**外层**（显示空间容器），旋转 `transform` 留在**内层**视频盒（与现状一致，只是多一层 overflow 的裁剪窗口）。`ProductPreview` 与加工视图**同一套嵌套结构**。

### 19.5.3 三个消费点

| 位置 | 现状 | 改后 |
| --- | --- | --- |
| `pages/Editor`（局部放大页） | 全画面 + 可拖选区框 | **双态**：编辑态（现状）/ 预览态（套用裁剪，框不可拖） |
| `pages/Workbench/EditModeView`（加工·放大 tab） | 同上 | 同上 |
| `components/ProductPreview`（成品预览） | 旋转已套用；裁剪**只画一个虚线框**，画面仍是整帧 → `BUG-015` | **直接出裁切放大后的画面**（虚线框不再画）；"该片段有放大"由块/卡徽标与 tooltip 承载 |

**双态交互**（`ADR-035`）：预览区一个切换控件（与工作台预览区既有的"成品预览 / 源剪切 / 片段加工"三态切换同风格的按钮组）；**编辑态**下选区框可拖拽、数值字段生效；**预览态**下选区框不可交互（只读，可隐藏），切回编辑态保留选区。两态切换**不重置**选区。

**为什么必须双态而不是"直接改成预览态"**：选区框画在"被裁掉的画面"上没有意义——框选交互与套用结果在同一画面里自相矛盾。同理也不能常驻分屏：两页的预览区宽度已被右侧操作面板挤占（`h-[44vh]` / 固定 `w-64`），分屏会把两半都压到不可用。用户 2026-09-28 裁决取双态。

**规格落点**：`DESIGN.md` §3.5（`FR-354` + `AC-354-1`）与 §3.8（成品预览措辞收紧，`BUG-015` 的依据）。**验证**：`TC-045`（成品预览首帧 vs 导出首帧同构图）+ `TC-046`（双态切换与选区保持）。

## 19.6 `M14-6` 片段池手柄语义修正

**这不是缺陷，是决策**：`DECISIONS.md` #13 明写"工作台顺序语义只在合成时间轴，片段池不做独立排序"，`DESIGN.md` §3.8、`UI.md` §9.8、`components/ClipPool` 头注释三处同口径，`BUGS.md` 无对应条目。用户"像是 bug"的感受来自**接口误导**：

- 池卡右下角用了 `GripVertical`（竖向抓取手柄）——长着"排序手柄"的样子，实际语义是**拖入时间轴**（`onDragStart` → 时间轴的 `externalDrag`）；
- 池标题行的提示文案是"拖手柄入轴"，与图标语义不一致。

**方案（用户裁决 A：不翻案，只消除误导）**：

1. 图标 `GripVertical` → `ArrowRight`（横向指向时间轴），`title` 统一为"拖入时间轴"；
2. 池标题提示收敛为一句："**池内不排序（顺序只在时间轴上表达）；拖卡片到时间轴即可加入**"；
3. `UI.md` §9.8 与 `components/ClipPool` 头注释同批更新，避免下次再被当成 bug 报（`ADR-036` 已记录该定性）。

**不做**：池内排序（要翻 `#13`，需新 ADR，且池序只是库存视图序，与成品顺序无耦合）、池的排序按钮（`CAND-021` 之外的新范围）。
