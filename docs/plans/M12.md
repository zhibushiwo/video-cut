## 21.1 三条已裁决的前提（2026-10-05 用户裁决）

1. **队列引入低优先级**：用户任务（导出/加工）= 普通，`preview` 与 `proxy` = 低优先级。调度**优先挑选普通任务**，只有没有普通任务待跑时才启动低优先级；**不做抢占**。低优先级可被持续饿死属**刻意取舍**，不引入 aging。
   - 依据：规格 `TIMELINE.md` §17.6 承诺"不抢导出并发位"，但**原实现是纯 FIFO、无优先级概念**——该承诺当时无机制支撑，本次补齐（同处已把"既有排队机制即可"修订掉）。
2. **preview 文件只留当前一份**：新预览开跑前清掉旧文件；`cache_usage`/`clear_cache` 覆盖 `preview/` 子目录；不设体积上限。
3. **失败静默回退**：渲染失败（磁盘不足 / ffmpeg 非零退出）时回到虚拟连播，仅在预览区提示条说明，**不弹窗、不阻断编辑**。

**范围边界**：`B15`（`check_pipeline` facts 缓存）**复查后关闭**——probe 侧 LRU 已满足（§17.7 已注明）；`ADR-037` ⑧ 的"播放跳过删除区间"**另行立项**，不并入本批。

## 21.3 后端 A：任务系统（`src-tauri/src/task/manager.rs`）

**优先级**

- 新增 `pub enum Priority { Normal, Low }`，**仅内部**——不进 `StatusPayload`/`TaskSnapshot`，**前端契约与事件 payload 不变**。
- `TaskHandle` 加 `priority` 字段；队列元素由裸 `(id, job)` 改为带 `priority` 的结构。
- 调度取队（`scheduler_loop` 附近）：由 `pop_front()` 改为**优先挑选普通**——`queue.iter().position(|q| q.priority == Normal).unwrap_or(0)` 后 `remove(idx)`；同类内保持 FIFO；取消排水逻辑不变。

**同源单例（新增入口）**

- `submit_internal_singleton(sink, kind, label, dedup_key, priority, job)`：
  - 同 `(kind, key)` 且既有任务仍活动 → **复用既有 `taskId`**（React StrictMode 双提交幂等）；
  - key 不同 → **在同一临界区内**：置旧任务 cancelled、Pending 则同时出队、取走其 killer；`dedup.remove(旧 key)`；`dedup.insert(新 key, 新 id)`；新任务以 `priority` 入队。
  - 出锁后：旧任务若为 Pending 则补 `record_terminal` + `run_cleanup`；有 killer 则调用；再 emit 新任务并唤醒调度。
- `submit_internal` **保留原语义**（复用、Normal），proxy 改走低优先级入口。

**竞态结论（必须写进测试）**

| 旧任务当时的状态 | 处理 |
| --- | --- |
| Pending | 同锁内出队 → 作业体**不执行**；出锁补终态与 cleanup |
| Running | 置 cancelled + 调 killer；worker 自然收尾走终态 → cleanup；**不等待、不抢占** |
| 已终态但 cleanup 未跑 | 登记时旧任务已非活动 → 直接写新 key；旧 `run_cleanup` 是 `retain(|_, v| v != old_id)`（**按 value 比较**）→ **不会误删新条目** |

**新增单测**：`normal_priority_selected_before_low` · `low_priority_runs_when_no_normal` · `singleton_same_key_reuses_active` · `singleton_new_key_cancels_old` · `singleton_replace_keeps_new_dedup_entry` · `queued_singleton_cancel_runs_no_job` · `internal_pipeline_hidden_from_snapshot`。

## 21.7 风险与披露

| 风险 | 影响 | 对策 / 披露 |
| --- | --- | --- |
| `CAND-015` 收窄 asset scope 时漏掉缓存目录 | 预览播不出 | 写进 `AC-1760-1`：**scope 必须含 `app_cache_dir`** |
| WebView2 持锁导致旧文件删不掉 / `atomic_replace` 失败 | 缓存残留、预览不更新 | 唯一令牌名 + 删除失败忽略 + `clear_cache` 兜底；**绝不复用旧文件** |
| 低优先级被持续饿死 | preview/proxy 长时间不跑 | 已裁决**接受**（preview 会被新编辑取代、proxy 只是预热）；不引入 aging |
| 不抢占：2 个任务占满时导出需等待 | 导出变慢 | 已裁决接受；代码注释写明是刻意取舍（抢占会带来状态机复杂度） |
| 缓存盘空间预检只查缓存盘 | 与导出盘空间无关 | 沿用 `require_disk_space`；低频场景，风险表披露 |
| internal 终态条目滞留任务 map | 内存缓慢增长 | 由既有 `clear_finished` 回收；singleton 提交时可顺带清同 kind 终态旧条目 |

## 21.8 手测点

1. 工作台纯无损时间线：编辑（排序/切割/修剪）停顿约 1.5s → 预览区自动切到**真实成品**、边界不再有切换停顿；播放/暂停/seek 与原先一致。
2. 含重编码片段时：**不**自动渲染，仍走虚拟连播；页脚「精确预览」可手动触发。
3. 制造渲染失败（如磁盘不足）：静默回退虚拟连播 + 提示条说明，不弹窗。
4. 设置页缓存统计包含 preview 占用；「清理缓存」后预览目录为空。
5. 预览渲染进行中：任务面板无新增行；同时手动导出正常完成（不被预览抢占）。
