# 变更日志（CHANGELOG）

> **职责**：记录**用户可见**的功能与行为变更（新增、变更、修复、移除），按版本成段。
> **唯一真源**：用户可见变更的对外表述以本文为准；**实现级细节**在各批次提交与 [handoff-archive.md](./archive/handoff-archive.md)，本文不重复。
> **读时机**：发版前整理发布说明；用户问"这版有什么变化"。
> **写规则**：只记用户可见项；只追加不重写历史段；开发中的变更先进 `[Unreleased]`，发版时切成 `[x.y.z] - YYYY-MM-DD`。**不抄 git log**（工程面改动如 lint/重构/文档整理不入本文）；**修复类条目须引 `BUG-0NN`**。

### 新增
- **剪切（无损优先）**：在源时间轴上选区间一键导出。「极速」模式 stream copy，秒级、画质与源一致；「精确」模式重编码到帧。一次可剪出多个片段（`part_001`、`part_002`…）
- **合并**：多文件按序拼接。参数一致时无损秒级完成、大小≈各源之和；不一致时列出 ⚠ 差异清单，可选「自动统一后合并」（重编码，速度慢、画质有损）
- **旋转**：顺/逆时针 90°、180°、水平/垂直翻转。默认只改方向元数据（秒级无损），需要把方向写进像素时可选重编码
- **局部放大**：框选画面区域、放大回原分辨率输出（必然重编码，可选质量档位/编码器）
- **自动代理预览**：播放器打不开的格式（AVI / FLV / TS / WMV、无 HEVC 扩展时的 H.265、10bit/HDR 等）自动生成 720p 代理用于预览，**导出仍使用原文件**；可关闭，关闭时只提示不阻塞
- **任务队列与面板**：全局并发 2、后台进度 / 速度 / 预计剩余、随时取消（不留半成品）、完成后可一键打开所在文件夹
- **历史记录**：任务终态落盘、只读可查、可清空
- **设置**：输出目录、编码器锁定、代理模式、关键帧吸附、质量档位、主题色、缓存统计与清理、关闭窗口确认、恢复默认值
- **工作台（多文件流水线）**：素材卡 → 片段池 → 合成时间轴 → 一次导出成品。同一素材可剪出多个片段，每段可单独旋转 / 放大，再在时间轴上任意编排
- **成品预览**：按时间轴顺序连播全部片段（套用各片段变换），播放头与时间轴双向联动，可 seek
- **时间轴编辑**：`C` 在播放头处切割 · 拖动片段块边缘修剪（可吸附关键帧，`S` 键开关、按住 `Alt` 临时旁路）· `Delete` 波纹删除（片段池保留库存、可再用）· 整块拖拽重排 · `Ctrl+Z` / `Ctrl+Shift+Z` 撤销重做（覆盖切割 / 修剪 / 删除 / 重排 / 批量合成）· `Ctrl+滚轮` 以鼠标为中心缩放、`+` / `−` 键、`\` 适应窗口 · 点击或拖动标尺定位播放头，靠近片段边界时吸附
- **时间轴右键菜单**：片段 —— 切割 / 波纹删除 / 移除并删除池片段（二次确认，可撤销）/ 加工 / 撤销 / 重做；空白 —— 撤销 / 重做 / 适应窗口
- **快捷键**：空格 播放/暂停 · `←/→` ±1 秒 · `Shift+←/→` 逐帧 · `I` / `O` 设入/出点（时间轴上 = 把选中片段的入/出点修剪到播放头）· `K` 暂停 · `L` 正放（连按在 0.5/1/1.5/2× 之间循环加速）· `A` 追加到时间轴末尾 · `Ctrl+E` 导出 · `Delete` 波纹删除片段
- **拖入视频文件即可导入**（落在当前页面，不跳转）
- **工作台成品预览会自动"渲染成真"**：纯无损的时间线停手约 1.5 秒后，后台自动把成品渲染出来、预览区直接播放**真实成品文件**——真正所见即所得，片段之间不再有切换停顿；含重编码片段时（渲染较慢，不自动跑）页脚可手动点「精确预览」。渲染产物存在缓存里（设置页的占用统计与「清理缓存」已覆盖），**不抢手动导出的并发**，也不出现在任务面板与历史记录里；渲染失败会静默退回原来的近似连播并说明原因

### 变更
- **工作台「片段池」的提示不再让人误以为能排序**：池卡右下角此前是一个竖向抓取图标、提示写作"拖手柄入轴"，看起来像排序手柄（池本来就**不排序**——顺序只在时间轴上表达）。现在图标改为横向箭头、提示写明"池内不排序（顺序只在时间轴上表达）；拖卡片到时间轴即可加入"

### 修复
> 记录**已修复的 BUG**，条目引用 `BUG-0NN`（真源 [BUGS.md](./BUGS.md)）；写用户可见的效果，不写实现细节。
- **任务内部意外出错只失败该任务，不再拖住队列、也不会带崩程序**：作业体里的意外 panic 此前会让该任务永远停在"进行中"并占住并发位（连续两次就冻结整条队列），打包版更会直接终止程序。现在统一收敛为"该任务失败"并写明原因，其余任务照常（`BUG-001`）
- **极速剪切的成品比界面承诺更长**：界面写着片段 2.7s，产物却是 4.036s。原因是无损剪切只能从关键帧开始，而吸附值被取整到了目标时刻之前，ffmpeg 遂退到再前一个关键帧。修复后成品时长与起播画面与界面一致（`BUG-007`）
- **入点显示的不是实际落点**：非吸附入点在无损剪切下会从一个更早的关键帧起播，偏差最大可到一个 GOP 而界面上看不出来。现在界面直接标出"实际入点"，并在时间轴画出落点虚线（`BUG-009`）
- **关键帧刻度丢项**：一部分关键帧（含最开始的 `0.0`）没有画出来，导致最长间隔被放大。修复后刻度条数与源文件一致（`BUG-008`）
- **导出时不再丢掉已有文件**：此前覆盖同名产物是"先删旧文件、再改名"，一旦改名失败（目标被别的程序占着、只读等），旧文件已经没了、新产物只剩一个 `.part`。现在由系统一步替换，失败则旧文件与新产物都留着，并明确告诉你新产物在哪个路径（`BUG-002`）
- **拖拽把鼠标拖出窗口再松手不再"卡住"**：此前在窗口外松手收不到结束事件，拖拽状态会一直挂着——之后随便动一下鼠标，选区/播放头就跟着乱跑，列表还会莫名重排。现在四处拖拽（裁剪框选、列表排序、时间轴手柄、片段拖入时间轴）都能正确收尾（`BUG-003`）
- **裁剪数值框填了越界数字不再"提交成功、跑到一半才失败"**：填入超出画面的 X/Y 时，此前会生成一个越界选区，报错要等任务跑起来才出现。现在锚点会自动收进画面内、宽高按剩余空间收缩（恰好在边界上仍可用），实在放不下（低于最小尺寸）就直接不提交（`BUG-004`）
- **用鼠标框选裁剪时把选区拖到画面边缘也不再失败**：此前左右/上下边缘各自取偶会各多出最多 1 像素，叠加后选区会超出画面 1~2 像素（导出时表现为"跑到一半才失败"）。现在选区边缘统一对齐，最多收回到画面边界（`BUG-010`）
- **导出成与源"同一个文件"时会被拦下，源视频不会再被自己的导出覆盖**：此前只有当输出路径与输入**逐字符完全相同**才拒绝；写法一变——大小写不同、末尾多一个点/空格、用 `..` 绕一层目录——程序就认不出来，照常导出并把**源视频覆盖掉**（不可逆）。现在这些都按"同一个文件"处理并拒绝，并告诉你与哪个输入撞车（`BUG-011`）
- **合并页有个别文件抽不出画面时，其余文件的缩略图照常显示**：此前只要有一个文件读不了帧，整组缩略图都不显示，看起来像功能坏了；现在只跳过那一个文件（`BUG-005`）
- **导出文件的扩展名不再与封装打架**：此前把非 mp4 素材做旋转/放大/合并，产物可能叫 `.mkv` 而内容其实是 MP4（播放器按扩展名判断时会出问题）；精确剪切 `.mkv` 素材又会产出 `.mkv` 封装。现在统一为：**无损类跟随源容器**（源是 mkv 就还是 mkv）、**重编码类固定 mp4**，你给的文件名会按封装自动校正；校正后若撞上已有同名文件，仍按老规矩追加时间戳而**不会静默覆盖**（`ADR-033`）
- **AVI / FLV / TS / WMV 等格式不再"看起来能播、点开是黑的"**：这些文件的画面编码（H.264）和音频编码（AAC）本来"单独看都支持"，于是程序不去生成预览代理，但播放器其实打不开这些封装，预览就黑着。现在这类文件会照常生成代理并正常预览；mp4 / mov / mkv / webm 仍然直接播放、不做多余转码（`BUG-006`）
- **切不出来的"极短片段"不再变成整段视频**：时间线切割 / 修剪的下限此前与导出阈值不一致——不足 0.05 秒的半段，导出时会被当成"空段"而**保留整段源文件**。现在下限统一为"1 帧与 0.05 秒取大"，切不出来就当场不生效，不会再给你一份整段视频（`BUG-012`）
- **工作台导出的进度不再提前跳到 100%**：逐段处理之后还有"参数归一化"与"拼接"两个阶段，此前进度公式把它们算成了绝对值，进度条一过第一段就顶到 100%、剩余时间也不再显示。现在三个阶段按真实比例推进（`BUG-013`）
- **工作台的成品预览能连续播完整个时间轴了**：此前播到第一个片段的末尾就停住（按钮弹回"播放"），只能逐个片段点开看。现在片段之间会自动接力播下去，播到时间轴末尾正常停止；中途点时间轴或拖进度条跳到任意位置后也能继续播（`BUG-014`）
- **成品预览里的局部放大不再"只画个框"**：带放大的片段此前在预览里仍显示整帧、只叠一个选区虚线框，看起来和导出结果对不上。现在预览直接显示放大后的构图（与导出画面一致），是否带放大改由时间轴/片段卡上的徽标提示（`BUG-015`）
- **工作台「片段加工」下方的时间条终于按这个片段来画了**：此前源视频 30 秒、片段只有 5 秒时，进度条和读数仍按 30 秒显示，还能把滑块拖到片段区间外面（一松手画面又被"弹"回入点）。现在刻度、读数与键盘左右键都以**片段区间**为准（`mm:ss / mm:ss` 直接读片段内的位置），也拖不出区间之外了（`BUG-016`）
- **从中间剪出来的片段播完一遍后能再播了**：此前（尤其片段起点不在视频开头时）播到出点停下后，点「播放」会出现"进度条跳回起点、按钮没变、画面却不动"；现在会正常从头重播，连点几次也能正常起来。顺带修好进度条到不了终点的问题——播到出点时滑块能贴到最右端了（`BUG-017` / `BUG-020`）
- **播放按钮不再"说谎"**：预览的播放源被换掉时（例如后台刚生成好预览代理、画面从原文件切到代理），视频已经停住了、按钮却一直显示「暂停」，再点也没反应——看起来像"点了播放却不播"。现在按钮始终如实反映画面状态：换源后回到「播放」，点一下就能正常播（`BUG-018`）
- **工作台成品预览播完后再点「播放」能重播了**：此前只有"从中间剪出的片段"会卡住——播到 3 秒处的末尾停下后再点播放，画面纹丝不动（连点多少次都一样）；把整个视频当作一个片段则一切正常，所以一直没被当成同一条问题。原因是"到片段末尾"和"到成品末尾"共用一条判定，而停下时画面正停在这条判定的边界内，再点播放会在第一帧又被自己按停。现在播到时间轴末尾后再点「播放」＝从成品开头重播，多段成品也从第一段重新开始（`BUG-021`）
- **从中间剪出的片段，重播"点下去就有反应"了**：此前点「播放」后要等 1~2 秒（要把画面回退解码到片段开头）才开始动，而这段时间按钮一直显示「播放」、画面静止——看起来就像"点了没反应"，于是再点一下，结果每次连点都把上一次还没起来的播放打断，重播就此永远起不来。现在点下去按钮立刻变「暂停」、画面在解码到位后自动接上，连点也不会把重播点没（`BUG-022`）
- **片段加工里"点画面"和点「播放」按钮是同一条走带了**：此前画面点击只走最简单的"没播就播"，不经过"停在出点先回到入点"的区间逻辑——片段播完停在末尾后点画面，只会起一帧又被按停，怎么点都重播不了（点按钮才正常）；顺带修好"自然播完一遍后按钮仍显示「暂停」、要点两次才能重播"（`BUG-023`）
- **播放遇到解码错误能自己恢复了**：此前某些视频在"往回重播"时，播放器底层的解码管线会崩溃（WebView2 的 `PIPELINE_ERROR_DECODE`）——此后画面永久静止，点多少次「播放」都只有事件没有画面，只能重启应用。现在播放器检测到这类错误会自动重建解码管线、回到原位继续播，全程无感知（`BUG-024`）
