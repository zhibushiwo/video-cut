# 变更日志（CHANGELOG）

> **职责**：记录**用户可见**的功能与行为变更（新增、变更、修复、移除），按版本成段。
> **唯一真源**：用户可见变更的对外表述以本文为准；**实现级细节**在各批次提交与 [handoff-archive.md](./archive/handoff-archive.md)，本文不重复。
> **读时机**：发版前整理发布说明；用户问"这版有什么变化"。
> **写规则**：只记用户可见项；只追加不重写历史段；开发中的变更先进 `[Unreleased]`，发版时切成 `[x.y.z] - YYYY-MM-DD`。**不抄 git log**（工程面改动如 lint/重构/文档整理不入本文）；**修复类条目须引 `BUG-0NN`**。
> **关联**：[INDEX.md](./INDEX.md) · 进度 [PLAN.md](./PLAN.md) · 缺陷 [BUGS.md](./BUGS.md) · 历史实现 [handoff-archive.md](./archive/handoff-archive.md)
> **最后更新**：2026-09-23（写入 `BUG-004`/`BUG-010`/`BUG-005` 三条修复）

格式遵循 [Keep a Changelog](https://keepachangelog.com/zh-CN/1.1.0/)，分类固定为：新增 / 变更 / 修复 / 移除。

### 修复
> 记录**已修复的 BUG**，条目引用 `BUG-0NN`（真源 [BUGS.md](./BUGS.md)）；写用户可见的效果，不写实现细节。
- **任务内部意外出错只失败该任务，不再拖住队列、也不会带崩程序**：作业体里的意外 panic 此前会让该任务永远停在"进行中"并占住并发位（连续两次就冻结整条队列），打包版更会直接终止程序。现在统一收敛为"该任务失败"并写明原因，其余任务照常（`BUG-001`）
- **极速剪切的成品比界面承诺更长**：界面写着片段 2.7s，产物却是 4.036s。原因是无损剪切只能从关键帧开始，而吸附值被取整到了目标时刻之前，ffmpeg 遂退到再前一个关键帧。修复后成品时长与起播画面与界面一致（`BUG-007`）
- **入点显示的不是实际落点**：非吸附入点在无损剪切下会从一个更早的关键帧起播，偏差最大可到一个 GOP 而界面上看不出来。现在界面直接标出"实际入点"，并在时间轴画出落点虚线（`BUG-009`）
- **关键帧刻度丢项**：一部分关键帧（含最开始的 `0.0`）没有画出来，导致最长间隔被放大。修复后刻度条数与源文件一致（`BUG-008`）
- **导出时不再丢掉已有文件**：此前覆盖同名产物是"先删旧文件、再改名"，一旦改名失败（目标被别的程序占着、只读等），旧文件已经没了、新产物只剩一个 `.part`。现在由系统一步替换，失败则旧文件与新产物都留着，并明确告诉你新产物在哪个路径（`BUG-002`）
- **拖拽把鼠标拖出窗口再松手不再"卡住"**：此前在窗口外松手收不到结束事件，拖拽状态会一直挂着——之后随便动一下鼠标，选区/播放头就跟着乱跑，列表还会莫名重排。现在四处拖拽（裁剪框选、列表排序、时间轴手柄、片段拖入时间轴）都能正确收尾（`BUG-003`）
- **裁剪数值框填了越界数字不再"提交成功、跑到一半才失败"**：填入超出画面的 X/Y 时，此前会生成一个越界选区，报错要等任务跑起来才出现。现在锚点会自动收进画面内、宽高按剩余空间收缩（恰好在边界上仍可用），实在放不下（低于最小尺寸）就直接不提交（`BUG-004`）
- **用鼠标框选裁剪时把选区拖到画面边缘也不再失败**：此前左右/上下边缘各自取偶会各多出最多 1 像素，叠加后选区会超出画面 1~2 像素（导出时表现为"跑到一半才失败"）。现在选区边缘统一对齐，最多收回到画面边界（`BUG-010`）
- **合并页有个别文件抽不出画面时，其余文件的缩略图照常显示**：此前只要有一个文件读不了帧，整组缩略图都不显示，看起来像功能坏了；现在只跳过那一个文件（`BUG-005`）
