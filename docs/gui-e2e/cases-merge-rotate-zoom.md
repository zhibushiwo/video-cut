## TC-034 合并：一致性检测、无损拼接、自动统一

- **覆盖**：FR-330 · FR-331 · FR-332 · FR-333 → AC-331-1 · AC-332-1 · AC-332-2 · AC-333-1
- **关联缺陷**：BUG-005（缩略图整批中止）· BUG-006（容器未纳入 `needsProxy` 判定）
- **夹具**：`video/merge_test_a.mp4` + `video/merge_test_b.mp4`（参数一致，可无损 concat）；另备一个 4K HEVC（不一致源，手工放入）

### 步骤

1. 合并页加入 a、b 两个文件 → 记录面板显示的参数与缩略图是否齐全。
2. 直接合并 → 记录耗时与产物路径。
3. 再加入 4K HEVC 源 → 读 ⚠ 面板列出的不一致项与建议。
4. 走「自动统一」后合并 → 核验产物。

### 断言

- **一致组**：合并耗时在秒级（copy 链路，接近磁盘速度）；产物时长 == 各源时长之和（±0.6s）；流数量与 `codec_name` 与源一致（**不得重编码**）；分辨率 == 源。
- **接缝可播**（关键）：在**第一个源的时长位置前后各取 1s** 解码一遍。只验总时长抓不到 concat 时间戳损坏——历史上出现过"时长对但 seek/播放坏"。
- **不一致组**：面板必须逐项列出差异（分辨率 / 帧率 / 编码 / 像素格式 / 时间基 / 音频参数等），自动统一后产物分辨率与帧率统一、全帧可解码。
- 只要有一个源无法抽帧，**其余缩略图仍要显示**（BUG-005 的回归口径）。

### 现状

✅ **无损链路通过（2026-09-19，命令级等价验证）**：210MB 双文件 concat → 43.091s（与 a+b 之和一致）、1 视频流 + 1 音频流、h264/aac 原样、1920×1080、接缝前后可解码、全帧可解码。
⏳ 界面侧（面板/缩略图/自动统一）待真机复跑。

## TC-035 旋转：元数据路径必须零重编码

- **覆盖**：FR-340 · FR-341 · FR-342 → AC-341-1 · AC-341-2 · AC-342-1
- **夹具**：`video/merge_test_a.mp4`（横屏，无方向矩阵）；另备一个手机竖拍带 rotation metadata 的源（手工）

### 步骤

1. 编辑页打开夹具，做一次 **90° 元数据旋转**（不触发重编码的那条路径）→ 导出。
2. 再做一次 **90° 重编码旋转** → 导出。
3. 两个产物各自 ffprobe。

### 断言

| 路径 | 断言 |
| --- | --- |
| 元数据旋转 | **编码分辨率不变**（仍是 1920×1080，说明是像素原样 copy）；`side_data_list` 出现 `Display Matrix` 且 `rotation == 90`；时长与源一致（±0.05s）；流数量不变；耗时秒级、体积基本不变 |
| 重编码旋转 | 宽高**交换**（1920×1080 → 1080×1920）；音频保留；全帧可解码 |

两者都要过"全帧可解码"。"秒级 + 体积不变"是元数据路径的旁证——重编码不可能这么快。

### 现状

✅ **通过（2026-09-19，命令级等价验证）**：元数据 90° → 分辨率不变、`Display Matrix rotation=90`、时长不变；重编码 90° → 1080×1920。真机复跑待补。

## TC-036 局部放大：框选、越界钳制与回原分辨率

- **覆盖**：FR-350 · FR-351 · FR-352 · FR-353 → AC-351-1 · AC-352-1 · AC-353-1
- **关联缺陷**：**BUG-004**（`pxToCrop` 不钳制 x/y → 选区越界）
- **夹具**：`video/merge_test_a.mp4`（1920×1080）

### 步骤

1. 工作台把素材剪成片段 → 进入片段加工 → 「放大」模式。
2. 在预览上框选左上 1/4（约 960×540）→ 点「回原分辨率」→ 导出。
3. 数值微调：把 x/y 拖到**恰好压界**、再拖到**远超界**，记录界面给出的选区值。
4. 导出并在预览里核对放大区域是否与框选一致。

### 断言

- 产物分辨率 == 原分辨率（放大 = crop + scale 回原尺寸），全帧可解码。
- 框选区域与产物画面一致（取产物首帧与源对应区域比对缩略图）。
- **越界钳制**：x/y 不越界、宽高为偶数、最小尺寸有下限；"恰好压界"要能正常导出（`pxToCrop` 契约：过小或越界返回 `null` → UI 必须拦住，不得提交越界裁剪）。
- 提交越界裁剪时**不得**产出 ffmpeg 报错的半成品（`commands` 层应已挡掉）。

### 现状

⏳ **待跑**。BUG-004 已在评审阶段定性（见 [BUGS.md](../BUGS.md)），其回归口径为 TC-022；本用例补的是**真机 GUI 侧**的端到端确认。
