## 17. 单轨装配时间线（M11–M13，2026-09-16 立项）

> 来源：用户时间线需求稿（三轨结构/磁吸/边缘修剪/拖拽重排等 13 节，2026-09-15）经讨论收敛为**单轨轻量版**。产品定位是"剪切合并更好用、预览做好、导出快"——时间线的职责是**看得见的拼接驾驶舱**，不是编辑器（决策 #26）。架构参照同栈开源编辑器 Clypra（Tauri 2 + React 19 + Rust + FFmpeg）已验证的结论：只采纳精度公式、撤销范式与性能契约思想，不抄其多轨/合成/原生渲染工程（要点见 [handoff-archive.md](./archive/handoff-archive.md)「时间线需求收敛」）。

### 17.1 时间线宪法（不变量）

1. **单轨、有序、永远连续**：时间线 = 片段 id 有序表（DESIGN.md §3.8 `timeline: string[]` 不变），片段位置由顺序推导；**没有空隙模型**，"允许留空隙"设置不做
2. **片段 = 源内区间** `[in, out)`（秒 f64，DESIGN.md §5.2 既有约定）：一切修剪只改区间端点；"波纹"是顺序表模型的自然结果（位置重算），无需专门实现，也永远不可能产生意外空隙
3. **音频永远跟随片段**（决策 #27）：无音频轨 UI，声音经 `-map 0` 原样导出，音画同步由模型免费保证
4. **所有操作可撤销**：时间线操作全部走撤销栈（§17.5），一次用户手势 = 一条撤销记录
5. **导出路径不变**：时间线任何操作的结果都映射为 `PipelineItem[]`；后端 pipeline 语义零改动（唯一例外见 §17.6 预览变体）

### 17.2 操作 → 数据模型映射（后端零必须改动）

| 时间线操作 | 前端数据变化 | 导出影响 |
| --- | --- | --- |
| 切割（播放头处） | 原片段拆为两条同源连续片段（新 clip 入池 + 入轴） | 两条 item；切割点非关键帧 → 该两条按规则 B 重编码 |
| 波纹删除 | 从 timeline 移除 id；**池卡片保留**（库存视图，决策 #13 一致） | 少一条 item，后续片段前移 |
| 边缘修剪 | 修改片段 `in/out`（受源边界与最短时长钳制） | 区间变化；切点是否关键帧决定 copy/transcode |
| 拖拽插入重排 | timeline 数组重排 | item 顺序变化 |
| 旋转/放大（既有加工模式） | clip 变换字段 | 规则 A/B 判定，不变 |

**源内切点换算**：产品内播放头 t → 命中片段 → `sourceSplit = clip.in + (t − clipTimelineStart)`（片段无变速；即 Clypra 精度文档 §4.1 公式的 speed=1 特例）。

### 17.3 坐标与精度（引用 Clypra 验证过的公式）· FR-1730（组级）

> FR-1731~1735 已随 `M11-1` 发号（2026-09-25）；各条的落地批次见行尾。

- **缩放单参数 PPS**（pixels/second，页面级状态）：`x = round(t × PPS)`，`t = x / PPS` · FR-1731（`M11-1` geometry，页面级状态 `M11-2`）
- **块宽差值法**：`widthPx = round(端点×PPS) − round(起点×PPS)`，**禁止** `round(时长×PPS)`——`round(a+b) ≠ round(a)+round(b)`，M9-3 块重叠 bug 的理论根源 · FR-1732（`M11-1`）
- **吸附窗**：`threshold = 8px / PPS`（秒）——屏幕像素定义，任何缩放下手感一致（采纳原需求稿 8px 设定） · FR-1733（seek 吸附 `M11-3`、修剪吸附 `M11-6`）
- **时间码格式化**：先 `round(t × fps)` 取总帧数，再分解时/分/秒/帧，避免 59.99s 显示成 00:59 的进位错 · FR-1734（`M11-1` `utils/time.ts::formatTimecode`）
- **最短片段**：≥ `max(1 帧, 0.05s)`，修剪与切割统一钳制 · FR-1735（`M11-0` 命令层建基线；**`M11-6` 随 `BUG-012` 裁决修订**——原"≥1 帧"与导出映射空段阈值 `MIN_SEG_DURATION_SEC`（M6-8）冲突，[1帧, 0.05s) 的短片段建得出来、导出却被规范成整段；裁决 = 命令层下限抬到与阈值对齐（`minSegSec`），导出映射不动、边界判定留 1µs 浮点容差；渲染侧动态 PPS 下限保证最短块 ≥6px，`M11-1` geometry）

### 17.5 撤销栈（B11 并入，决策 #29；命令模式）

- **结构**：`Command { apply(state), invert(): Command, toJSON/fromJSON }` + **纯函数 builder**——拖拽/切割/修剪在提交时以冻结快照计算 before/after **实体快照对**（不碰活状态）；no-op、取消、非法落点返回 null，不产生脏历史
- **快照对而非增量**：序列化 round-trip 天然可恢复会话（v1 不做持久化，留口）
- **粒度**：一次用户手势 = 一条命令（多片段整块拖拽亦然）；修剪的连续指针移动不入栈，pointerup 时提交一条
- **覆盖操作**：剪出片段（新建池条目并接入轴）/ 切割 / 波纹删除 / 修剪 / 重排 / 从池加入 / 移出时间轴
- 前端不引入状态库：命令层为纯 TS 模块（`utils/undo/`），直接作用于页面 state；**禁止绕过栈直接改 timeline 状态**
  - **例外：两类不可逆的联动清理**（直接写文档、走 `applyRaw`、不进历史）。① **素材删除**：删素材本身不可撤销（`files` 含 probe 副作用，属 [plans/M11.md](./plans/M11.md) §18.1 的旁路状态），它顺带移除的片段也只能直接写文档——否则会留下"片段还在、素材没了"的文档，导出映射出空 `input`。② **池卡 ✕ 真删**（[plans/M11.md](./plans/M11.md) §18.5 / 决策 #13）：时间轴 ✕ / Delete / 拖出边界是**可撤销**的波纹删除（只出轴、池保留），池卡 ✕ 才是真删——直接改文档、轴上残留项联动清。要做可撤销的删除，用时间轴上的"移除并删除池片段"（右键，走命令栈，M11-8）。
- 单测基线（照 Clypra 清单）：undo/redo 恢复逐字节一致、序列化 round-trip、no-op 不入栈、取消拖拽不入栈、撤销顺序正确（先撤销最近手势）、重做复现同一 id
- **撤销/重做接线**：Ctrl+Z / Ctrl+Shift+Z——**全模式可用**（时间轴常驻可见，与 Delete 同口径；栈空自然 no-op），输入焦点忽略由 useHotkeys 内建（输入框内 Ctrl+Z = 原生文本撤销）；一次手势一条，按键调用同包 undo 场景埋点；右键菜单的撤销/重做项随 M11-8 菜单接线、复用同一对 handler · FR-1736（`M11-7`）
- **外部删除清洗**（§18.9 风险的裁决落地）：池卡 ✕ 真删 / 素材删除走 `applyRaw` 不经栈，而快照对携带**全量** clips——**携带片段的**外部删除毒化全部历史（undo 会把被删片段"复活"；无片段素材的删除不触碰文档快照，不清栈，避免误杀其他片段的合法撤销历史）→ 真删了片段的外部删除发生时**整体清栈**（`useUndoStack.clear`）。裁决"整体清栈"而非"undo 前逐命令校验"：毒化必然是全栈性的，逐命令校验等价于清栈但更复杂 · FR-1737（`M11-7`）
- **快照语义披露**：撤销/重做按快照对恢复**全量**文档（含彼时的加工状态）——栈顶命令之后做的加工编辑（rot/crop/lockRatio，旁路不入栈）会被随后的撤销一并回退（§18.1 旁路状态不入栈的推论；行为有单测锁定）

### 17.6 预览（三层，按投入递增）

1. **虚拟连播改进（M12-1）**：下一段预加载提前、边界切换停顿缓解；修剪拖动时节流 seek 显示入/出点帧（UI.md §9.8 既有双 video 架构内优化）
2. **渲染即预览（决策 #28，本产品独有优势）**：纯无损时间线在编辑停顿 ~1.5s（防抖）后后台自动跑 preview pipeline，**播放真实成品文件**——100% 所见即所得、边界零停顿；含重编码片段的时间线回退虚拟连播，页脚提供手动"精确预览"按钮
   - **后端唯一必须改动**：`Pipeline` 任务加 `preview` 标志——输出强制写 `app_cache_dir/preview/<令牌>.mp4`；`TaskHandle` 加 internal 标志，`record_terminal` 跳过（不进历史）；进行中去重 = 新编辑取消旧 preview 任务（复用 proxy pending 机制与 kill/`.part` 清理）；`cache_usage`/`clear_cache` 覆盖 preview 子目录；磁盘预检沿用 `require_disk_space`（已接入 pipeline）

### 17.7 导出速度联动

- **关键帧吸附引导 copy 路径**：修剪边缘默认吸附关键帧（设置既有开关），切点落关键帧 → 规则 A copy 秒出；用户偏离时块徽标实时变 warn 并提示原因——"好用"与"导出快"是同一个交互，把性能基线第 4 条（"超出即回查误入重编码"）的防线前移到操作时

### 17.9 性能与验收（预算表）

| 指标 | 预算 | 验证方式 |
| --- | --- | --- |
| 拖拽/重排/修剪跟随 | 指针移动到绘制 < 1 帧（60fps） | 100 片段夹具 + 帧时间埋点（logger，报 P50/P95） |
| 播放头刷新 | 不触发整树 re-render（ref 直改 DOM，脱离 React 状态路径） | React DevTools commit 计数 |
| 撤销/重做 | < 16ms | 100 片段重排撤销计时 |
| seek 响应 | < 100ms | 埋点 |
| 渲染即预览 | 纯无损时间线 ≤ 10s（SSD，沿用"测试与质量约定 4"基线） | 夹具实测 |

**`M11-9` 计量记录（2026-09-25）**：命令层（撤销/重做）已在纯函数层计量——100 片段重排 execute max=0.289ms / undo max=0.126ms / redo max=0.011ms，比 16ms 预算低两个数量级（数字见 TESTING TC-043 自动化半）；**drag/playing 的帧预算（P95 ≤ 16.7ms）与 seek 响应（< 100ms）走真机报告**（步骤见 [plans/M11.md](./plans/M11.md) §18.6 引的 gui-e2e 用例，⏳ 待用户发起）——React 渲染半不计入命令层计量。

**验收清单**：① 七操作全链可用且全部可撤销（含撤销后重做逐字节一致）；② 100 片段拖拽/播放头不掉帧（埋点达标）；③ 修剪关键帧吸附生效、徽标实时反映 copy/transcode；④ 波纹删除/修剪/重排后时间线永远连续无意外空隙；⑤ 任意时间线状态导出正确（B14 e2e 思路补 pipeline 参数断言）；⑥ 纯无损时间线预览即真实成品文件且连续可播。

### 17.10 v1 明确不做（防反复）

多轨/叠加/转场；音频轨 UI（波形、音量线、淡入淡出、分离、替换）；空隙模型与"允许留空隙"设置；黑场片段、禁用片段；调色；复制/粘贴变换；命令面板；覆盖/插入双编辑语义；J 倒放（`<video>` 不支持反向播放，随预览引擎决策再看）；多选/框选与标记轨（M13 可选，决策 #31）；章节标记。

> 需求稿中与单轨模型冲突的条目（分离音频后的波纹错位、"仅视频/仅音频"选择、B 覆盖编辑在连续模型下与插入等价、允许空隙伤有序表模型）已按决策 #26/#27 裁决，详细理由见 [handoff-archive.md](./archive/handoff-archive.md)「时间线需求收敛」。
